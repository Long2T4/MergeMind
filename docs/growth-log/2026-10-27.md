# 2026-10-27

## Base stylesheet imported after component styles silently wins

- **Root cause**: `main.jsx` imported `App` (which pulls in every page and
  component stylesheet) *before* `index.css`. Base rules such as `.card { padding }`
  and `.btn { display }` therefore came later in the bundle and overrode
  component rules of equal specificity. That's why the mobile menu button
  showed on desktop and the "Submitted code" card got double padding.
- **Rule**: Import global/base CSS first in the entry file, then the app.
  Component styles should only need equal specificity to override base styles.
- **Signal**: A component rule "doesn't apply" even though DevTools shows it,
  struck through by a same-specificity rule from the global stylesheet.

## Visually hidden text can widen the page from inside a scroll box

- **Root cause**: `.sr-only` uses `position: absolute`. Inside a table in an
  `overflow-x: auto` card with no positioned ancestor, those elements are
  laid out relative to the page, not the card. They escape the card's
  clipping and add horizontal page scroll (159 px at 1024 px wide).
- **Rule**: Any container that clips or scrolls (`overflow: auto/hidden`) and
  holds `.sr-only` or other absolute children needs `position: relative`.
- **Signal**: The page scrolls sideways, but no visible element overflows.
  Searching for elements past the viewport finds nothing visible.
